## 4. Tasks

### Task 1 — Palette module
- `src/client/visuals/palette.ts`: `PaletteId`, `PaperSwatch`, `PresentationPalette`, `PALETTES`, `getPalette`, `applyPaletteCssVariables`, with the exact shapes in interface §1.
- Three variants `a`, `b`, `c` in the cream / brick red / mustard / teal / soft green family. The `town` values are first proposals for D1; the user picks the final palette at D1. Variant `a` keeps today's paper hexes (`0xc0392b`, `0x2980b9`, `0x27ae60`, `0xd4ac0d`, grey `0x7f8c8d`) so the town and UI agree until Codex moves `PAPER_COLOR_HEX` in D1/D2.
- CSS variables: `--nt-paper`, `--nt-ink`, `--nt-panel`, `--nt-border`, `--nt-accent`, `--nt-danger`, `--nt-focus`, `--nt-paper-red|blue|green|gold`, `--nt-unsubscribed`.
- Tests: `css` and `hex` agree per swatch; labels present; `applyPaletteCssVariables` sets every variable; WCAG contrast ink-on-panel and ink-on-paper ≥ 4.5:1 and focus ring ≥ 3:1 for every variant.

### Task 2 — Tokens and base styles
- `theme.css` keeps only non-color tokens. A test fails if any `src/client/styles/*.css` file contains a hex, `rgb(`, or `hsl(` literal, so themed colors stay in `palette.ts` (shadow alpha uses `color-mix` with `--nt-ink`).
- Typography: newspaper feel from a system serif stack for headings (`Georgia, 'Times New Roman', serif`) and a system sans stack for body. See open question Q1.
- `:focus-visible` outline from `--nt-focus` on every control.

### Task 3 — Component, HUD, and screen styles
- Coverage test (`tests/ui/css-coverage.test.ts`): repeats the diagnosis method (static `className` strings in `src/client/ui`, template stems resolved against their known values such as `btn-primary`, `paper-color-red`) and fails if any used class lacks a rule. Expected: 0 missing (today 142).
- Layout:
  - Top bar: fixed, full width, round badge, phase title, timer (server deadline via existing `CountdownTimer`), controls.
  - Standings: compact left panel at desktop; below 640 px it becomes a horizontal scrolling strip under the top bar.
  - Action panels (intro, investigate, write, reveal, lobby, home, join): bounded cards, `max-height` inside the viewport with internal scroll, bottom-center at desktop, full-width bottom sheet below 640 px. The town stays visible around them.
- Paper identity: color stripe plus the existing icon and name (`PaperBadge`); never color alone.
- States: hover, `:disabled`, selected, locked; reduced motion respects the existing `.reduced-motion` and media query.
- Long text: `overflow-wrap: anywhere` on names and headlines; controls never pushed offscreen.

### Task 4 — Reader labels
- `PaperView` gains `totalReaders` (from `PaperPublic.totalReaders`; the client copies, never computes).
- Standings show "Readers now N" and "Total readers N". Scoreboard column "Total readers".
- The formula line comes from `TUNING.scoreTrustDivisor` instead of the hard-coded `50`: "Score = Total readers × Trust ÷ 50, rounded" (matches `src/engine/score.ts`).
- Tests: HUD/SidePanel and FinalEditionScreen show both labels and the formula derived from `TUNING`.

### Task 5 — Results card
- `FinalEditionScreen`: one centered card bounded to the viewport; header (title + winner, with trophy icon and text), score table, then the scrollable history section titled "The truth comes out" (headline archive). "Final edition scandals" and "Integrity records" become native `<details>` sections, collapsed by default.
- The card body scrolls; the "Play Again" footer stays visible. The table wraps names; below 640 px the table scrolls horizontally inside the card, not the page.
- Keep the existing loading state ("Tabulating…").
- Tests: winner text, labels, sections present, `details` collapsed, Play Again works.

### Task 6 — Loading, empty, and error states
- Style `loading-screen`, `final-loading`, `connection-modal`, `reconnecting-pill`, `server-restart-screen`, `screen-error-banner`, `hud-error-banner`, `mod-error-banner`, locked states.
- Audit each screen for loading, empty, and error states (AGENTS.md UI note). Add a missing state only where it is absent; list each addition in the handoff.

### Task 7 — Capture extension (shared command)
- New flags: `--screen <name>` for `--target app` and `--palette a|b|c` (both targets; on `town` it is recorded in the sidecar and passed in the URL, and Codex wires it into the renderer in D1).
- Screens:
  - `home` (default, as today), `join` (clicks "Play Solo"), `lobby` (clicks "Create Room", fills the form, submits). These use the real dev server, with no fake data.
  - `match`, `loading`, `disconnected`: a new dev-only harness page `src/client/visual-test/app.html` mounts the real `AppRouter` and the town over a fixture-fed `createClientStore` with the virtual clock, using `--fixture/--round/--phase` like the town target. The session comes from a stubbed `send` that acknowledges `playSolo` with a session through the store's public `receive` API. `loading` stops before the first snapshot; `disconnected` calls `setConnection('disconnected')`.
- Ready signal: the harness publishes `window.__NEWS_TOWN_VISUAL__` after the expected `data-testid` is present, `document.fonts.ready`, and town readiness.
- The harness stays out of `vite build` (checked after build, as in C0).
- Tests: argument parsing and scenario parsing for the new flags.

### Task 8 — Screenshots and inspection
- Matrix at 1280×720 and 390×844: home, join, lobby, intro, investigate, write, reveal (`solo-honest`), final and ended (`solo-honest` round 5), loading, disconnected, and one error banner.
- Palette check: the round-1 investigate screen in `a`, `b`, `c`.
- Every PNG viewed with the Read tool; findings recorded in the handoff. PNGs stay in the scratchpad, not committed.
