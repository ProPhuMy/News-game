> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a sample bakery and representative street props as modules that match the acknowledged presentation interface. Evaluate code-built and kit-hybrid construction with inspected screenshots, record asset licenses, and hand Codex everything D1 needs.

**Architecture:** Building and prop factories live in `src/client/town/architecture/` and `src/client/town/props/`. They receive an `ArchitectureContext` (palette, `MaterialKit`, `AssetSource`) and return a `PlacedPiece`. `createTownBuildings` gains an optional context plus `ready` and `dispose`. With no context it behaves as today, so Codex's renderer and every existing test keep working until D1 wires the context in. A new dev-only harness scene renders the sample at a fixed camera through `npm run capture -- --target architecture`. In that scene a harness-only preview `MaterialKit` and `AssetSource` stand in for Codex's D1 implementations.

**Tech Stack:** TypeScript (strict), Three.js 0.186 (`GLTFLoader` from `three/examples/jsm`, already used by Codex's inspection scene), Vitest, `playwright-core` capture (C0). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-14-visual-overhaul-design.md` §3, §4, §5, §8, §9 and §13 (C2 row). Interface: `docs/visual-overhaul/presentation-interface.md` §1–§5.

**Branch:** `claude/c2-architecture-sample` from local `main` `b50d081`. Dependency C1.5 passed and is merged (`ae85167`; `handoffs/C1.5.md` §7). C2 does not depend on D1.

## Global Constraints

- Ownership (AGENTS.md): Claude writes only `src/client/visuals/`, `src/client/town/buildings.ts`, `src/client/town/architecture/`, `src/client/town/props/`, `public/models/buildings/`, `public/models/props/`, `tests/town/buildings.test.ts`, `tests/town/architecture/`, `tests/town/props/`, `src/client/visual-test/`, `scripts/visual/`, `tests/visual/` and `docs/visual-overhaul/`. **Never edit `ASSETS.md`** (Codex is its only editor), `src/client/town/index.ts` or any other Codex file.
- `src/shared/` is frozen. Map nodes, routes and anchors do not move (spec §4). A piece's root goes at its node's world position.
- Interface rules (note §2–§3): pieces never create lit materials. Every surface comes from `ctx.materials.surface(hex, options?)`, and every hex comes from `ctx.palette`. The one exception is the hybrid `original` mode, which leaves a loaded glTF material untouched. Pieces never dispose kit materials or `AssetSource`-cached geometry or textures. Origin at ground (y = 0) in the footprint center, and +Z faces the street.
- A recoverable load failure inserts a code stand-in and adds a `degraded` entry. It is never silent.
- Scale reference: D1 evaluation citizen height is `3.29` world units (D0: 2 × 1.6449). `GRID.spacing = 12`, road width `3.4` (`src/client/town/environment.ts:21`).
- Assets must be CC0. Commit each pack's `License.txt` next to its files. Nothing loads from third-party URLs at runtime.
- No new dependencies. Files stay under about 300 lines. Named exports. No `any`.

## Review Focus

1. **A kit model fails to load** (missing file, bad URL): the piece shows a code stand-in, `ready` lists `degraded`, and the capture fails with `degraded-assets: …`. Pinned in Tasks 3 and 4.
2. **Dispose**: `dispose()` called twice does not throw. It never disposes kit materials or loaded geometry. Pinned in Tasks 2 and 3.
3. **A Nature Kit material name missing from the role map** falls back to `trim` and is listed in `degraded`, so a new model can never ship off-palette silently. Pinned in Task 4.
4. **Palette swap**: every hex passed to `surface()` is a `palette.town` value, and switching palette `a` to `b` changes the colors. No hex literals in the modules. Pinned in Tasks 2 and 4.
5. **Footprint vs streets**: the bakery footprint fits a lot (width and depth ≤ 12 − 3.4 = 8.6), and its door is at least 1.25 × the 3.29 citizen height. Pinned in Task 2.
