How the capture works: the CLI picks a free port, launches headless Chromium (without `DISPLAY`/`WAYLAND_DISPLAY`), then starts `src/server/index.ts` (dev mode, `AI_PROVIDER=none`) and waits for it, failing at once if the server exits. For `--target town` it opens `/visual-test/index.html?...`: the harness applies the fixture frames up to the requested round/phase, installs a virtual clock (stubs `Date.now`, `performance.now`, `requestAnimationFrame`, `cancelAnimationFrame`, seeded `Math.random`), mounts the town through `mountTown` with a `preserveDrawingBuffer` renderer, awaits `whenReady()` if present, advances exactly `reactionMs`, measures the canvas (≥16 distinct colors required) and publishes `window.__NEWS_TOWN_VISUAL__`. For `--target app` it opens `/` and waits for `[data-testid="home-screen"]`. It writes `<out>.png` and `<out>.png.json` (scenario, browser version, ready state, stylesheet responses, console errors). Any failure exits 1, deletes the PNG, and stops the browser and server.

Usage: `npm run capture -- --out <file.png> [--target town|app] [--fixture solo-honest] [--round 1] [--phase reveal] [--reaction-ms 6000] [--reduced-motion] [--seed 1] [--width 1280] [--height 720] [--prod] [--timeout-ms 60000]`. `--prod` needs `npm run build` first and supports only `--target app`.
