## 11. Final whole-branch review and fix pass

A fresh reviewer read the whole branch (`7457fd0..f1cd9e2`). It reported no Critical findings, three Important ones and four Minor ones. All three Important findings were fixed, each with a test that failed first:

1. **The layout check could pass broken layouts.**
   - `pageOverflowX` could never be true under `position: fixed`.
   - Any scrolling ancestor counted, even one that ran past the viewport.
   - Clipping by an ancestor that cannot scroll was not detected.
   - **Fix:** the check is now the pure function `layoutProblems` in `scripts/visual/layout.ts`. The browser only collects the box tree.
   - **Tests:** `tests/visual/layout.test.ts`, 6 tests. "Rejects a control whose scroll panel runs past the viewport", "rejects a control cut off by a clipping ancestor" and "reports any element wider than the viewport" were RED before the module existed. "Skips elements without a box" was RED against the first version.
   - **Mutation check:** adding `.results-card { min-width: 600px }` makes the phone capture fail with `layout: overflowX: section.final-card.results-card, ...`. The CSS was reverted afterwards.
2. **The HUD error banner was hidden after the player had acted** in investigate or write. The acted panels show no error, so the error was lost.
   - **Fix:** the banner is suppressed only while the phase panel can show the error (`!privateSnapshot.acted`).
   - **Test:** "keeps the HUD error banner after the player has acted, when the panel shows no error" (RED, then GREEN).
3. **Focus ring hidden on the selected color button.** `.selected` used `outline`.
   - **Fix:** the selected state uses `box-shadow`.
   - **Test:** "never marks a selected control with outline". Viewed in `review/join-tab3.png`: the teal ring shows on the selected Red button.

Suite after the fix pass: 84 files, 471/471. Typecheck 0, lint 0. Matrix re-run clean.
