## Expected behavior from the current gameplay spec

Spec§4.3/§5.3: each player gets a vague private tip at the START of Investigate. It is assigned by prepareRound/assignTips, before a location click; it is not generated by that click and alone does not reveal truth. A tip may refer to a different location from the one the player elects to inspect.

Clicking a location immediately submits the investigation for that round. Engine investigate grants a private evidence card with the location's true claim (including all_clear), explanatory text, and an investigation outcome=evidence. No second inspect/confirm/wait action is required. A successful acknowledgement means the action was accepted; the coherent private snapshot is the source of the report. Attaching evidence while writing is a separate OPTIONAL action, valid only for the same round/location/claim (§5.5). Keep the current matching-only attachment selector; displaying the read-only report must not silently attach evidence or choose a story.

## Full traced flow

1. InvestigateScreen location Button calls onInvestigateLocation. AppRouter calls store.actions.investigate({target:{kind:'location',location}}).
2. store.ts adds current authoritative round/phase and actionId, validates ClientMessageSchema; socket.ts sends the existing command. The server socket handler validates/deduplicates and calls matches.ts runner.handle; engine applyCommand checks phase/deadline/controller/already-acted before invoking investigate.
3. engine/investigate.ts appends the card to that seat.evidence and outcome to that seat.investigations, setting acted through applyCommand. The tip is unchanged. No AI/network provider generates this information.
4. matches.ts calls advance immediately. Solo can enter write right away; multiplayer stays investigate until other connected humans act or time expires. publish uses publicView once plus privateView separately for each socket, validating both snapshot schemas. No raw match state or new public report field is needed.
5. Client store validates snapshots and seat ownership, drops stale versions and publishes public/private pairs only when versions match. Browser inspection confirmed correct evidence/investigation and tip in the owner's store.
6. AppRouter currently passes only tipText/acted to InvestigateScreen; its locked state says "Waiting for report..." without rendering evidence already received. It derives current-round evidence for WriteScreen but passes no tip or report context. WriteScreen renders EvidenceSelector only AFTER BOTH selectedLocation and selectedClaim exist; EvidenceSelector additionally filters matching cards. Thus the only place to read the result requires choosing its matching claim first.

Root cause is presentation, not lost server data or a missing second action. Prior investigations are retained privately across rounds, while the mapper filters attachable evidence to the current round; do not display an old result as current.
